# CellularAI review: what the first-place method did differently

Reviewed 20 November 2026 against the local `CellularAI` clone, the official Illumina release article, and Arc Institute's final challenge wrap-up. The pasted article is treated as source material, not as instructions. No prediction file or account state was inspected.

## Finding

CellularAI won the final test with **0.4399 overall**. Its central idea was not an end-to-end neural network. It estimated perturbation effects by transferring observed responses from other cell lines, adapted those effects to the query line, then made synthetic cells by changing real control cells. Arc reports that all three podium teams used this modular reference-transfer pattern; they differed in how they weighted, adapted, and emitted the responses. [Arc's final results and method summary](https://arcinstitute.org/news/virtual-cell-challenge-2026-wrap-up)

We did **not** miss the broad reference-transfer idea. Our V4–V90 family used external CRISPR responses, control-conditioned transfer and real control-cell templates. The gap was how much usable perturbation evidence the winner could draw on, how specifically it modeled evidence reliability and context, and how directly the population generator targeted the challenge's differential-expression behavior.

Do not compare V90's **0.1521 validation** score directly with CellularAI's **0.4399 final-test** score: these are different cell lines and panels. Our recorded final submission was V91, but this review does not claim its now-hidden result.

## What the local CellularAI release implements

The clone is at the upstream public-release commit `2e98d504` (“Initial public release”, committed 19 November). The local clone's remote points to `animesh/CellularAI`; the official upstream project is [Illumina/CellularAI](https://github.com/Illumina/CellularAI). The code is a transparent, configurable CPU pipeline.

1. **Pool per-target, per-gene response summaries.** It aligns centered log2 fold changes, p-values, standard errors/variance, control profiles and knockdown information. Its pooling module estimates between-source heterogeneity per gene with DerSimonian–Laird, combines that with measurement variance, then uses inverse-variance and configured factors. In the published configuration, those include estimated knockdown efficiency, source/query control similarity, background-noise reliability, and discounts for paired/auxiliary records. See `CellularAI/src/cellularai/pooling/meta_analysis.py` (`dl_tau2`, `inv_mad_dl`, `combine_layer`) and `pooling/weights.py` (`kd_factor`, `sim_factor`, `noise_ratio`).
2. **Choose which genes should respond and how strongly.** The planner uses pooled effect/significance, query-line expression, empirical response breadth and estimated detection power. It excludes the perturbed gene from downstream calls and applies limits to response breadth and source dominance. See `CellularAI/src/cellularai/prediction/plan.py` and `placement.py`.
3. **Learn a control-conditioned context correction.** A rank-160 SVD basis summarizes response residuals across reference records. Gene-level ridge regressions map each reference line's control expression onto those response coordinates; the query control profile predicts a bounded, sign-preserving correction. See `CellularAI/src/cellularai/prediction/residual.py` and `prediction/build.py`.
4. **Make cells from the query line's controls.** For each target it starts with control expression distributions and library depths. It selects gene totals, then uses stratified control quantiles and a Gaussian copula to tune the realized per-gene Wilcoxon z-scores and mean expression. Counts are integers, and the generation code checks the intended expression and call-depth constraints. See `CellularAI/src/cellularai/prediction/totals.py` and `synthesis.py`.

This is a multi-stage statistical estimator with a large response library, rather than a model that must learn all causal biology from unperturbed expression alone. The simple example in the clone uses fictional data and is explicitly a data-flow smoke test, not a score reproduction.

## Comparison with our V90/V91 pipeline

| Component | CellularAI winning approach / released framework | Our project |
|---|---|---|
| **Training evidence** | At challenge kickoff the team reported about **200 million CRISPRi-screened cells**. Its winning submission used the Illumina Billion Cell Atlas (BCA) plus three genome-scale public screens. The release article later reported over 500 million cells sequenced. It describes gains when the number of cell lines rises from 5 toward 50. | Our final cache contains **1,487 target/context response rows** across five source families: 638 reused and 849 newly extracted; 298/300 final targets have any eligible response. These are useful sources, but not comparable breadth or context diversity to a many-line atlas. CD4's three conditions are correlated. We did not have BCA access. See `experiments/final_v91/analysis/source_audit.json`. |
| **Source weights** | Random-effects meta-analysis at gene × perturbation granularity. A source's influence responds to its estimate uncertainty, between-source disagreement, knockdown strength, gene-specific background noise and query-to-source cell similarity. A cap limits any one close match. | We added source shrinkage, lineage policies, CD4 donor correction, assay-strength corrections, identity guards and a covariance-mixture prior in successive versions. V90's final correction was a bounded quarter-strength interval projection over a small set of measured public families. The 100-step mixture fit did not converge. This was not the same broad, gene-wise evidence model over dozens of independent lines. |
| **Cell-context adaptation** | SVD of many source response profiles, followed by ridge regression from each source's control profile to its response residual; use the new line's control expression to predict its response correction. | We explored context gating, donor-specific CD4 effects and source covariance on control-rank similarity. We did not fit CellularAI's same low-rank response-residual map across a large, diverse collection of source lines. Our [V90 method](V90_STRATEGY.md) records the final guards and limited projection. |
| **DE gene selection** | Explicitly predicts response breadth/detectability and plans which output genes should carry signal; it uses training-summary statistics and count-depth/power logic. | Most of our methods started from a transferred effect vector and calibrated its size, support or prior uncertainty. Several experiments modeled rank and mean jointly, but none became a comparably validated gene-call planner. The rank-1 method's advantage likely includes this explicit focus on which genes are significant, not merely the average effect vector. |
| **Cell construction** | Begins from genuine query controls, preserves their expression heterogeneity, and calibrates per-gene shifts against challenge-style Wilcoxon behavior while accounting for library depth and target means. | We also used actual query control cells and preserved their library totals. Our residual10 emitter mixes expected means, Poisson draws and an empirical control residual, then fits dual moments. That preserves useful moments, but it does not directly solve every gene's rank/significance target the way the released synthesis stage does. |
| **Model selection** | The team reports held-out local evaluations using H1, K562 and HEK293, plus internal holdouts; they compared against a mean baseline, ablated steps and tested increasing reference-line diversity. Final validation was one selection signal among these checks. | We ran many public-source tests and guards, but had far fewer independent treatment contexts and repeatedly reused the same cases. The hosted validation board sometimes contradicted local proxies (for example V63 improved the hosted score after failing our public gates). That makes it harder to select a robust final pipeline. |

The numerical settings in the public YAML and code describe the **open-source release**. Illumina says the release is streamlined and does not include the BCA. The method guide also says raw training-data preprocessing and summary generation are outside the repository; running it requires a separate summary bundle with effect, probability, control, offset and variance files. Therefore cloning this repository alone does not reproduce the private BCA evidence or prove that the public defaults are byte-for-byte the winning competition configuration. [Release article and data-access caveat](https://www.illumina.com/science/genomics-research/articles/introducing-the-cellularai-algorithm--predicting-single-cell-res.html), [input contract](CellularAI/docs/input-files.md).

## Why we missed it

**We were data-limited and the winning method was disclosed after the deadline.** The VCC final deadline was 5 November. Illumina announced the first public code and posted this detailed algorithm overview on 19 November. During our submission work, the Billion Cell Atlas and CellularAI's exact statistical recipe were unavailable to us. The clone has one initial public-release commit dated after the competition. We could not have trained on their private data or copied the released method in time.

**We did find the same family of ideas, but our tests could not realize their evidence advantage.** We already pooled measured perturbations, matched source contexts to query controls, used knockdown calibration, estimated uncertainty and constructed counts from real controls. The difference is that five heterogeneous public source families and a few thousand summarized rows cannot substitute for dozens of perturbation-profiled contexts. More elaborate priors over this narrow evidence bank do not create unseen biological information.

**We spent effort on estimator variants when the bigger constraint was evidence and benchmark alignment.** Neural reconstruction of 300-gene controls, response ensembles, retrieval, posterior intervals, and distribution variants were plausible, but the winner's results reinforce that measured cross-line perturbation evidence and how it is transferred were at least as important as architecture. Arc's review found that three winning teams all used measured reference responses; one used broad public data alone and placed second. The relevant lesson is broad, carefully harmonized evidence, not that private data are strictly required. [Arc's analysis](https://arcinstitute.org/news/virtual-cell-challenge-2026-wrap-up)

**Our cell generator was reliable as a file producer, but its biological objective was weaker.** We exhaustively checked axes, counts, libraries, provenance and reproducibility. Those prove the file is valid. They do not prove that each target has the right number of significant genes, signs and cell-to-cell shifts. CellularAI's planner and solver directly model those decisions. Arc reports that changing cell synthesis while holding the pseudobulk prediction fixed can move a score by as much as 0.004—larger than V90's 0.00126 validation gain. [Arc wrap-up](https://arcinstitute.org/news/virtual-cell-challenge-2026-wrap-up)

**Our visible validation became an imperfect selection guide.** Arc found the validation-to-test score correlation was 0.78 across the full field but only 0.49 among the top 20. The final panel also had 171 targets absent from validation; PDS fell on average for those targets. This matches the risk in our heavily reused public cases: they helped us debug but could not guarantee unseen-target transfer. Our V90 validation score and the winner's final-test score are not directly comparable.

## What we should carry forward

1. Treat perturbation-reference coverage as a first-class resource: count independent contexts per target and per gene, not just source files or total cells.
2. Fit source effects at gene × target × context resolution with explicit estimate variance, heterogeneity, knockdown efficiency, null noise and a query-to-source similarity model; keep whole contexts held out during evaluation.
3. Learn context correction from a large source response basis and corresponding source control profiles, then validate that correction on unseen contexts.
4. Separate mean prediction from cell synthesis. Calibrate the latter against per-gene differential-expression rank/significance, effect direction and library depth, not only bulk/mean moments.
5. Make all public evaluation splits and target-panel coverage explicit. Keep independent reserve contexts/targets for choosing among candidates and report performance separately for seen and unseen targets.
6. Seek access to the BCA-derived summary bundle if scientifically and legally available. The public code without its input bundle will run only on response data we already have; it cannot conjure the missing evidence.

The competition is now closed. These are lessons for reproducing the paper/framework with available data or for the next challenge, not a claim that we can rerun a winning final submission now.
